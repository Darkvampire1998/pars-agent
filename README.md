# Pars Agent — پنل مستقل ترید MT5

نسخه ۰٫۳٫۰ | ۸ اکتبر ۲۰۲۶

یک برنامه قابل نصب روی VPS لینوکس با رابط فارسی، ثبت‌نام چندکاربره، چند حساب برای هر کاربر، تحلیل کندل‌های واقعی متاتریدر، پنج استراتژی، اجرای سفارش از طریق اکسپرت MQL5 یا کانکتور SDK و گزارش تلگرام.

طراحی از ساختار صفحه [CapitalSolo / SAGE](https://ai.capitalsolo.com/stock/BTC-USD/last-idea) الهام گرفته است: فضای تیره، نمودار مرکزی، واچ‌لیست و آخرین ایده‌ها. داده، کد، برند و API خصوصی آن سایت استفاده نشده است. بخش اخبار شبکه‌های اجتماعی آن سایت در این نسخه پیاده نشده است.

## وضعیت این تحویل

کد پنل و سرور ساخته و آزمون‌های خودکار آن اجرا شده‌اند. فایل اکسپرت، تنظیمات Docker، HTTPS و راهنمای نصب همراه بسته است. راه‌اندازی نسخه ارتقایافته روی VPS، ورود SDK به بروکر و سفارش واقعی باید در محیط مقصد آزموده شود. فایل MQL5 در MetaEditor این محیط کامپایل نشده است. بنابراین این تحویل، تأیید آمادگی معامله واقعی یا سودآوری نیست. فایل EX5 پس از کامپایل در محیط شما تولید می‌شود.

| قابلیت | رفتار نسخه حاضر |
|---|---|
| چندکاربره | حساب، تنظیمات، گزارش و کلید اتصال هر کاربر مستقل است؛ حداکثر ۱۰ حساب برای هر کاربر |
| نمودار | کندل‌های بسته از ترمینال MT5؛ بدون داده نمایشی ساختگی |
| استراتژی | EMA، RSI رنج، Donchian، پول‌بک روند، بازگشت Bollinger؛ سیاست adaptive/consensus/priority |
| انتخاب بازار | نام دقیق نماد بروکر؛ M5، M15 و H1؛ حداکثر ۲۰ نماد در هر حساب |
| اجرای خودکار | حالت‌های تحلیل، حساب دمو و حساب واقعی؛ حساب واقعی به دو فعال‌سازی جدا نیاز دارد |
| کنترل ریسک | اندازه سفارش در ارز حساب با OrderCalcProfit، سقف ریسک همزمان، افت روزانه/کل، تعداد پوزیشن، اسپرد، لغزش و مارجین |
| توقف | توقف ورود جدید و لغو سفارش‌های آماده؛ پوزیشن‌های باز خودکار بسته نمی‌شوند |
| تلگرام | توکن و Chat ID از پنل؛ نتیجه سفارش، دیل‌های ورود/خروج، گزارش روزانه و درخواست گزارش ۲۴ ساعت |
| گزارش | سود تحقق‌یافته دیل‌های دریافت‌شده با کارمزد و سواپ؛ ثبت رویداد تغییر تنظیمات و سفارش |
| اتصال امن | کلید جدا برای هر حساب، ذخیره هش کلید، رمزگذاری توکن تلگرام؛ در روش اکسپرت رمز در ترمینال می‌ماند؛ در کانکتور رمز با کلید سرور رمزگذاری می‌شود |
| دسترسی با IP | HTTPS روی IP عمومی و پورت دلخواه؛ صدور و تمدید خودکار گواهی کوتاه‌مدت IP |
| مدیریت سرور | منوی ترمینال برای وضعیت، شروع/توقف، ری‌استارت، لاگ، آپدیت، بکاپ و بررسی شبکه |

این ایجنت یک موتور خودکار مبتنی بر قواعد است؛ مدل زبانی، پیش‌بینی سود، درصد برد تضمینی یا اتصال مخفی به سرویس AI ندارد. راهبردها نمونه قواعد پیاده‌شده‌اند و هنوز از نظر عملکرد معاملاتی اعتبارسنجی نشده‌اند.

## ارتقای نصب موجود و ورود با رمز MT5

برای پنل نصب‌شده، اسکریپت نصب فعال را دوباره اجرا نکنید؛ از آپدیت استفاده کنید:

```bash
sudo bash /opt/pars-agent/deploy/manage.sh update
```

کانتینر نسخه جدید پیش از توقف برنامه دانلود می‌شود و بکاپ تنظیمات/دیتابیس گرفته می‌شود. schema جدید با CREATE TABLE IF NOT EXISTS اضافه می‌شود. تنظیمات حساب‌های قبلی، کلید رمزگذاری و داده‌ها حفظ می‌شوند؛ سیاست و ریسک قبلی خودکار عوض نمی‌شوند. در پنل، انتخاب پروفایل «محافظه‌کار» تنظیمات پیشنهادی نسخه جدید را اعمال و ایجنت را متوقف می‌کند.

بخش جدید منوی مدیریت، گزینه **۱۰: MT5 account connection** است؛ یا مستقیم:

```bash
sudo bash /opt/pars-agent/deploy/manage.sh connect
```

این گزینه ایمیل/رمز پنل، حساب MT5، شماره ورود، نام دقیق سرور و رمز معاملاتی را با ورودی خصوصی دریافت می‌کند. رمز MT5 رمزگذاری می‌شود و به‌صورت plaintext در فایل‌های نصب ذخیره نمی‌شود. اتصال بروکر تنها پس از اجرای کانکتور و تأیید داده حساب موفق است.

همین مسیر در پنل «حساب و اتصال» وجود دارد؛ برای حساب قبلی، فرم «ورود کانکتور» رمز را تغییر می‌دهد و کلید قبلی را باطل می‌کند. **رمز متاتریدر را در چت ارسال نکنید**؛ آن را در پنل HTTPS یا ورودی خصوصی منوی سرور وارد کنید.

بسته کانکتور از پنل دانلود می‌شود و SDK رسمی و NumPy برای Windows Python 3.12 x64 را به‌صورت wheel آفلاین همراه دارد. اجرای کانکتور روی Windows با ترمینال بروکر نصب‌شده، یا Windows Python داخل Wine آماده انجام می‌شود. نصب پنل Docker، Wine/ترمینال را خودکار نصب نمی‌کند. راهنمای دقیق: [mt5/README.md](mt5/README.md). برای هر حساب، ترمینال و state مستقل لازم است. اکسپرت MQL5 همچنان مسیر جایگزین است و باید فایل نسخه ۰٫۳ جداگانه کامپایل و جایگزین شود.

## موتور تصمیم و ارزیابی راهبرد

پروفایل محافظه‌کار جدید: M15، ریسک ۰٫۲۵٪ هر ورود، سقف ۱٪ ریسک باز، افت روزانه ۳٪ و کل ۶٪، حداکثر دو پوزیشن و شش ورود روزانه. ADX/ATR وضعیت روند، رنج و گذار را تعیین می‌کنند؛ adaptive در گذار یا شوک وارد نمی‌شود. consensus به تعداد رأی تعیین‌شده نیاز دارد. تضاد جهت، داده قدیمی، اسپرد زیاد، خروج‌های زیانده متوالی و وقفه بین ورودها مانع ورود می‌شوند.

در حالت محافظه‌کار، پوزیشن تکراری نماد و جهت ارز مشترک شناخته‌شده مسدود می‌شوند؛ این کنترل، تخمین آماری همبستگی نیست. در پل قدیمی که اطلاعات نماد پوزیشن‌ها را نمی‌فرستد، ورود با این کنترل‌ها هنگام وجود پوزیشن متوقف می‌شود و پیام ارتقای کانکتور می‌آید.

زمان شروع روز ریسک با اختلاف دقیقه از UTC قابل تنظیم است؛ ۲۱۰ یعنی تهران. این مقدار باید با قوانین حساب/پراپ تطبیق داشته باشد. رسیدن به حد ضرر روزانه، ایجنت را تا روز بعد متوقف می‌کند و بازگشت equity آن را روشن نمی‌کند. توقف کل به بررسی و رفع دستی در حساب متوقف، متصل و بدون پوزیشن نیاز دارد. توقف، پوزیشن بروکر را خودکار نمی‌بندد.

بخش «ارزیابی راهبرد» CSV واقعی `time,open,high,low,close` را می‌پذیرد؛ ۳۰۰ تا ۳۰۰۰ کندل با زمان Unix ثانیه به ترتیب قدیم به جدید. اندازه point، اسپرد، لغزش و کارمزد را از نماد بروکر بگیرید. ورود در کندل بعد، هزینه رفت‌وبرگشت، SL محافظه‌کارانه در کندل مبهم و آزمون هزینه دوبرابر منظور می‌شود. ۳۰٪ آخر جداست و پارامترها بهینه نمی‌شوند. این مدل OHLC ساده، همه شرایط بروکر و ریسک اجرای زنده را بازسازی نمی‌کند. نتیجه مثبت، تأیید سودآوری یا مجوز فعال‌سازی واقعی نیست.

روش تحقیق، منابع اولیه، دلیل انتخاب قواعد و محدودیت‌ها: [docs/RESEARCH.md](docs/RESEARCH.md).

## مسیر اتصال

پنل و موتور روی لینوکس اجرا می‌شوند. برای هر حساب، یک ترمینال MT5 روشن و **یک کانکتور** لازم است: کانکتور Python با SDK رسمی و ورود خودکار از اطلاعات ذخیره‌شده پنل، یا اکسپرت `ParsAgentBridge.mq5` با ورود دستی در ترمینال. هر دو با HTTPS کندل و وضعیت حساب را می‌فرستند و سفارش را بعد از کنترل ریسک اجرا می‌کنند. این دو را همزمان برای یک حساب اجرا نکنید.

ترمینال می‌تواند روی سیستم خود کاربر، VPS ویندوز یا لینوکس همراه Wine اجرا شود. نصب Docker پنل، متاتریدر را نصب نمی‌کند. برای میزبانی تمام حساب‌ها روی همان VPS لینوکس، ترمینال‌ها باید جداگانه آماده شوند؛ برای هر حساب یک کاربر سیستم‌عامل، Wine prefix و سرویس مستقل در نظر بگیرید. میزان RAM/CPU لازم به تعداد ترمینال‌ها و نمادها بستگی دارد و در این تحویل اندازه‌گیری نشده است.

طبق [راهنمای رسمی MetaQuotes](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)، اجرای MT5 روی لینوکس از Wine استفاده می‌کند. فایل `deploy/mt5-example.service` نمونه راه‌اندازی پس از نصب و ورود به حساب است؛ مسیرها را با نصب واقعی خود تطبیق دهید. برای VPS فاقد محیط دسکتاپ، آماده‌سازی Wine و ورود اولیه به حساب به محیط نمایش نیاز دارد. از ترمینال موبایل نمی‌توان این اکسپرت را اجرا کرد.

## نصب پنل روی VPS

### نصب آسان با IP

نصب پیش‌فرض، کانتینر آماده را از GitHub Container Registry دریافت می‌کند؛ **روی VPS هیچ بسته پایتونی با pip نصب نمی‌شود**. وابستگی‌ها پس از موفقیت آزمون‌ها در GitHub Actions داخل کانتینر نصب شده‌اند. نصب بدون ورود به گیت‌هاب انجام می‌شود و تصویر دانلودشده با revision کد تطبیق داده و با digest ثبت می‌شود.

روی Ubuntu/Debian، نصب‌کننده IP عمومی همین سرور را خودکار تشخیص می‌دهد:

```bash
curl --proto '=https' --tlsv1.2 -fsSL --retry 3 --connect-timeout 10 --max-time 90 https://raw.githubusercontent.com/Darkvampire1998/pars-agent/main/deploy/bootstrap.sh -o pars-agent-install.sh
sudo bash pars-agent-install.sh
```

تشخیص IP با دو سرویس HTTPS مستقل تأیید می‌شود؛ در صورت ابهام، نصب متوقف می‌شود و می‌توان `--ip YOUR_PUBLIC_IP` یا `--domain HOST` را صریح داد. این IP مربوط به VPS است، نه دستگاهی که از آن SSH زده‌اید.

برای نمونه، با IP `85.198.9.26` آدرس هدف پنل `https://85.198.9.26` است. آدرس فقط پس از پاسخ سالم سرویس و تأیید گواهی HTTPS موفق اعلام می‌شود. کاربر root می‌تواند `sudo` را حذف کند. از پورت پیش‌فرض ۴۴۳ برای اتصال اکسپرت MT5 استفاده کنید.

همین دستور، نصب ناموفق قبلی را در `/opt/pars-agent` **خودکار ادامه می‌دهد**؛ `--resume` و `--host-build-network` برای مسیر آماده لازم نیست. فایل `.env`، کلید رمزگذاری، تنظیمات و حجم داده حفظ می‌شوند. فقط checkout تمیز با origin و branch صحیح پذیرفته می‌شود؛ پوشه نامرتبط یا کد دارای تغییر محلی بازنویسی نمی‌شود. اگر پنل با همین آدرس از قبل پاسخ سالم HTTPS داشته باشد، دستور موفق خارج می‌شود؛ پنل فعال برای آپدیت از منوی مدیریت به‌روز می‌شود.

نصب فقط وابستگی‌های مفقود را نصب می‌کند؛ با وجود curl، Git، Python و CAها مرحله apt تکرار نمی‌شود. در صورت نبود Docker، نسخه رسمی Docker Engine نصب می‌شود. افزونه **Docker Compose 2.24.4 یا جدیدتر** لازم است. تصویر آماده برای Linux amd64 و arm64 منتشر می‌شود؛ پشتیبانی معماری کانتینر، به‌معنی آماده بودن MT5/Wine روی ARM نیست.

### دامنه، پورت و مدیریت

برای دامنه واقعی که DNS آن به VPS اشاره می‌کند:

```bash
sudo bash pars-agent-install.sh --domain trade.your-domain.com
```

TCP 80 و TCP 443 باید آزاد و در فایروال سرور/ارائه‌دهنده باز باشند. پورت ۸۰ برای صدور و تمدید گواهی لازم است. نصب‌کننده سرویس دیگر را متوقف و فایروال یا DNS سیستم را بازنویسی نمی‌کند. دسترسی پنل از مرورگر با `--port 8443` ممکن است، ولی اتصال اکسپرت روی پورت سفارشی اعتبارسنجی نشده است. گواهی IP با Caddy 2.11.7 و پروفایل shortlived از Let's Encrypt صادر می‌شود؛ صدور واقعی به شبکه سرور وابسته است.

```bash
sudo bash /opt/pars-agent/deploy/manage.sh
```

منو شامل وضعیت، شروع/توقف، ری‌استارت، لاگ، آپدیت، بکاپ، بررسی شبکه و آدرس پنل است. دستور مستقیم هم ممکن است:

```bash
sudo bash /opt/pars-agent/deploy/manage.sh logs
sudo bash /opt/pars-agent/deploy/manage.sh doctor
sudo bash /opt/pars-agent/deploy/manage.sh update
```

قبل از آپدیت، ایجنت‌ها و سفارش‌های معلق را بررسی کنید. توقف سرویس پوزیشن‌های بروکر را نمی‌بندد. در حالت آماده، آپدیت کانتینر نسخه جدید را **قبل از توقف پنل** دانلود و با revision تطبیق می‌دهد؛ سپس بکاپ تنظیمات/دیتابیس می‌گیرد و همان digest را اجرا می‌کند. فایل اکسپرت باید جداگانه در MT5 کامپایل و جایگزین شود.

### شبکه و مسیر ساخت از کد

نصب آماده به اتصال GHCR، رجیستری Caddy و Let's Encrypt نیاز دارد؛ خرابی `files.pythonhosted.org` مانع این مسیر نیست. بررسی DNS/TLS هر سرویس حداکثر ۱۰ ثانیه فرصت دارد؛ قطع بودن تلگرام فقط هشدار می‌دهد و پنل می‌تواند نصب شود. گزارش‌های تلگرام تا بازیابی اتصال ارسال نخواهند شد. هیچ بررسی TLS غیرفعال نمی‌شود و نصب بدون گواهی معتبر موفق اعلام نمی‌شود.

اگر دریافت کانتینر آماده شکست خورد، همان دستور را دوباره اجرا کنید و لاگ را بررسی کنید. نسخه مربوط به هر commit فقط پس از اتمام موفق آزمون‌ها و انتشار تصویر قابل دانلود است؛ لازم نیست رمز یا توکن گیت‌هاب را روی VPS وارد کنید. کپی‌های شخصی مخزن هم باید workflow انتشار و package عمومی خود را داشته باشند.

ساخت محلی برای توسعه یا شرایطی که GHCR قابل دسترسی نیست، به‌صورت اختیاری باقی مانده است و **به اتصال سالم PyPI نیاز دارد**:

```bash
sudo bash pars-agent-install.sh --ip YOUR_PUBLIC_IP --source-build
```

اگر میزبان به PyPI وصل می‌شود ولی فقط شبکه ساخت Docker خطای DNS دارد:

```bash
sudo bash pars-agent-install.sh --ip YOUR_PUBLIC_IP --host-build-network
```

این گزینه ساخت را با شبکه میزبان انجام می‌دهد؛ شبکه کانتینرهای اجراشده همچنان Compose است. Compose 2.27.1 یا جدیدتر لازم دارد. اگر DNS خود VPS خراب باشد، این گزینه آن را اصلاح نمی‌کند. تغییر DNS باید با تنظیمات شبکه واقعی و ارائه‌دهنده VPS تطبیق داده شود.

برای مسیر نصب دیگر، همان `--dir /opt/another-path` را در نصب/ادامه نصب بدهید. برای تغییر آدرس یک پنل فعال، ابتدا ایجنت‌ها را متوقف و بکاپ تهیه کنید؛ `deploy/configure.py --ip YOUR_PUBLIC_IP --reconfigure` آدرس را با حفظ کلید تغییر می‌دهد. پس از `docker compose up -d --force-recreate --wait` کاربران دوباره وارد شوند و آدرس WebRequest/PanelUrl اکسپرت را تغییر دهند.

### نصب از فایل ZIP

۱. روی VPS، Docker Engine و افزونه Docker Compose را از [راهنمای رسمی Docker](https://docs.docker.com/engine/install/ubuntu/) نصب کنید. Python 3 برای تولید تنظیمات لازم است. برای میزبانی MT5 با Wine روی همان دستگاه، VPS x86_64 انتخاب کنید؛ مسیر ترمینال ARM در این بسته فراهم نشده است.

۲. رکورد DNS زیردامنه، مثلاً `trade.your-domain.com`، را به IP سرور متصل کنید. پورت‌های ۸۰ و ۴۴۳ باید برای صدور گواهی و دسترسی HTTPS قابل استفاده باشند. این نام صرفاً مثال است؛ دامنه شما لازم است.

۳. فایل ZIP را روی سرور باز کنید و داخل پوشه پروژه اجرا کنید:

```bash
cd pars-agent
bash deploy/install.sh trade.your-domain.com --source-build
docker compose ps
```

نصب‌کننده یک کلید رمزگذاری اختصاصی می‌سازد، برنامه را اجرا می‌کند و Caddy برای دامنه تنظیم‌شده HTTPS فراهم می‌کند. آدرس پنل `https://trade.your-domain.com` خواهد بود. صدور گواهی به DNS و دسترسی شبکه سرور وابسته است؛ اسکریپت برای دامنه‌ای که هنوز تنظیم نشده آدرس فعال تولید نمی‌کند.

۴. وارد آدرس پنل شوید و حساب کاربری بسازید. رمز ورود حداقل ۱۲ کاراکتر است. در «حساب و اتصال»، نام حساب، شماره ورود، نام دقیق سرور بروکر و سرمایه مبنای محاسبه افت کل را ثبت کنید. کلید اتصال یک‌بار نمایش داده می‌شود؛ آن را داخل اکسپرت وارد کنید.

۵. در «استراتژی‌ها»، نام نمادهای موجود نزد بروکر خود را وارد کنید. `BTC-USD` نام منبع مرجع است و الزاماً نام نماد بروکر نیست؛ ممکن است `BTCUSD`، `BTCUSDm` یا نام دیگری باشد. اسپرد بر حسب **پوینت همان نماد** است؛ تنظیم EURUSD را بدون بررسی به طلا یا کریپتو منتقل نکنید.

### اجرای محلی سرور برای توسعه

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
python3 deploy/configure.py --local
set -a
source .env
set +a
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

این حالت برای بررسی سرور و رابط است؛ اکسپرت HTTPS می‌خواهد و به آدرس HTTP محلی متصل نمی‌شود. `.env` موجود را بازتولید نکنید: تغییر کلید رمزگذاری، توکن‌های ذخیره‌شده قبلی را غیرقابل خواندن می‌کند.

## آماده‌سازی اکسپرت MT5

۱. در MT5 گزینه `File → Open Data Folder` را باز کنید. فایل `mt5/ParsAgentBridge.mq5` را به `MQL5/Experts` منتقل کنید.

۲. در MetaEditor فایل را باز و با F7 کامپایل کنید. خطا یا هشدار را بررسی کنید؛ خروجی EX5 در کنار فایل ساخته می‌شود. کامپایل این مرحله در محیط تحویل انجام نشده است.

۳. در MT5 مسیر `Tools → Options → Expert Advisors` را باز کنید. WebRequest را فعال و **فقط مبدا HTTPS پنل خودتان** را به فهرست اضافه کنید. این الزام در [مستندات رسمی WebRequest](https://www.mql5.com/en/docs/network/webrequest) آمده است.

۴. یک نسخه اکسپرت را روی یک چارت قرار دهید و تنظیمات را وارد کنید:

| ورودی | مقدار |
|---|---|
| `PanelUrl` | آدرس HTTPS پنل، بدون `/` در پایان |
| `BridgeKey` | کلید همین حساب از پنل |
| `AllowRealTrading` | در شروع `false`؛ فقط برای حساب واقعی عمداً فعال شود |
| `PollSeconds` | پیش‌فرض ۳ ثانیه؛ حداقل ۲ |
| `MagicNumber` | شناسه سفارش‌های ایجنت؛ پیش‌فرض ۲۶۰۶۱۰۰۱ |

۵. Algo Trading ترمینال و مجوز معامله اکسپرت را فعال کنید. نام سرور و شماره ورود ترمینال باید دقیقاً مطابق حساب ثبت‌شده در پنل باشند. یک حساب نمی‌تواند همزمان به دو ترمینال با شناسه متفاوت متصل شود. برای انتقال به ترمینال جدید، ابتدا ایجنت را متوقف، سفارش‌های نامشخص را بررسی و سپس کلید را تعویض کنید.

۶. وضعیت «ترمینال متصل» در پنل باید ظاهر شود. حالت «فقط تحلیل» برای مشاهده تحلیل است. برای ارسال سفارش روی دمو، حالت را به «معامله خودکار حساب دمو» تغییر دهید، تنظیمات را ذخیره و ایجنت را شروع کنید. یک کندل جدیدِ دارای شرایط ورود لازم است؛ ایده قدیمی با شروع دوباره به سفارش تبدیل نمی‌شود.

برای حساب واقعی، علاوه بر `AllowRealTrading=true` در اکسپرت و انتخاب `live` در پنل، مدیر سرور باید `LIVE_TRADING_ALLOWED=true` را در `.env` تنظیم و سرویس را بازسازی کند:

```bash
docker compose up -d --force-recreate app
```

سرور در تحویل اولیه این قابلیت را بسته نگه می‌دارد؛ آزمون بروکر و مجوز بهره‌برداری عمومی هنوز انجام نشده است.

## چرخه سفارش و خطاها

استراتژی روی کندل بسته، ایده تولید می‌کند. سرور حدود ریسک و وضعیت حساب را بررسی می‌کند. سفارش ابتدا `prepared` است، سپس اکسپرت آن را یک‌بار `claimed` می‌کند. اکسپرت با اطلاعات تازه ترمینال، `OrderCalcProfit` و مارجین، حجم را رو به پایین و مطابق حداقل/گام لات بروکر محاسبه می‌کند. اگر حداقل حجم از بودجه ریسک بیشتر باشد، معامله رد می‌شود؛ حجم برای رسیدن به حداقل لات افزایش نمی‌یابد.

نتیجه اجرای قطعی `executed` یا `rejected` است. در تایم‌اوت یا پاسخ مبهم، وضعیت `unknown` می‌شود. سفارش `claimed` بدون نتیجه یا `unknown`، **ورود جدید تمام نمادهای همان حساب را مسدود می‌کند** و خودکار تکرار نمی‌شود. اکسپرت پیش از ارسال، یک فایل ژورنال محلی ثبت می‌کند و گزارش پاسخ را هنگام بازیابی اتصال دوباره ارسال می‌کند.

برای رفع وضعیت مبهم: ایجنت را متوقف کنید، پوزیشن‌ها و History بروکر را بررسی کنید، سپس در «معاملات و گزارش → تطبیق سفارش نامشخص» شناسه و نتیجه واقعی را ثبت کنید. اگر هنوز معلوم نیست، رفع مسدودی نکنید. گزینه «توقف ورود جدید» سفارش آماده را لغو می‌کند؛ سفارش قبلاً تحویل‌شده ممکن است در همان لحظه اجرا شود. برای بررسی/بستن پوزیشن موجود از خود ترمینال استفاده کنید؛ بستن دستی پوزیشن از این نسخه پنل فراهم نیست.

## کنترل ریسک و حدود محاسبه

- پیش‌فرض حساب جدید: ریسک ۰٫۲۵٪ هر معامله، ۱٪ ریسک همزمان، توقف روزانه ۳٪ و توقف کل ۶٪. تنظیمات حساب‌های قدیمی حفظ می‌شوند. این اعداد تنظیم نرم‌افزارند و توصیه سرمایه‌گذاری نیستند.
- تمام پوزیشن‌های حساب، حتی معاملات دستی، در ریسک باز منظور می‌شوند. پوزیشن بدون SL، شکست محاسبه ریسک یا وجود سفارش معلق، ورود جدید را مسدود می‌کند.
- ریسک باز، زیان احتمالی از **قیمت جاری تا SL** است. در گپ یا لغزش واقعی می‌تواند بیشتر شود. ذخیره هزینه، سقف قطعی زیان نیست.
- مبنای افت کل همان سرمایه اولیه ثبت‌شده است؛ trailing drawdown پیاده نشده است.
- روز کنترل ریسک بر اساس اختلاف دقیقه تنظیم‌شده از UTC است؛ مقدار اولیه صفر است. در اولین داده هر روز، مبنا برابر بیشترینِ بالانس فعلی، equity فعلی و آخرین equity روز قبل قرار می‌گیرد. اگر ترمینال مدت طولانی قطع باشد، این مبنا الزاماً equity دقیق نیمه‌شب نیست. قواعد روزانه هر پراپ باید جداگانه تطبیق داده شوند.
- واریز/برداشت و تعدیل سرمایه مبنا به‌صورت خودکار مدیریت نمی‌شود. با تغییر سرمایه حساب، معامله را متوقف و تنظیمات/حساب را بازبینی کنید.
- داده قدیمی‌تر از ۱۵ ثانیه یا قیمت قدیمی پذیرفته نمی‌شود. ساعت سیستم‌های سرور و ترمینال باید درست باشد.
- هیچ سفارش جدیدی با مدل زبانی یا محتوای اخبار تولید نمی‌شود. پنج استراتژی باید با ابزار ارزیابی OHLC پنل، داده مستقل تازه و حساب دمو بررسی شوند؛ ابزار پنل جای آزمون تیک و شرایط اجرای بروکر را نمی‌گیرد.

## اتصال تلگرام

با BotFather ربات بسازید؛ در چت مقصد ابتدا `/start` بفرستید. توکن و Chat ID را در پنل ذخیره و «ارسال پیام تست» را بزنید. وضعیت صف را بررسی کنید: قرار گرفتن در صف به معنی ارسال موفق نیست. `sent` ارسال موفق، `failed` پایان پنج تلاش و `skipped` یعنی اتصال گزارش غیرفعال بوده است.

گزارش روزانه برای روز بسته‌شده با ساعت UTC+03:30 ساخته می‌شود و در حالت عادی پس از ۰۰:۰۰ تهران ارسال می‌شود. در اولین اتصال، گزارش روز قبل نیز ساخته می‌شود. در راه‌اندازی پس از قطعی، آخرین روز بسته‌شده گزارش می‌شود؛ ارسال کامل همه روزهای ازدست‌رفته فراهم نیست. ارسال به اتصال شبکه VPS با `api.telegram.org` وابسته است. ربات فقط گزارش می‌فرستد؛ فرمان معامله از تلگرام در این نسخه وجود ندارد.

دیل‌های دریافت‌شده شامل معاملات دستی و ایجنت است. اکسپرت در هر ارسال، تازه‌ترین ۲۰۰ دیل هفت روز گذشته را می‌فرستد و سرور تکرارها را حذف می‌کند. گزارش ۳۰ روز، از داده جمع‌شده از زمان اتصال ساخته می‌شود؛ اتصال اولیه سابقه کامل ۳۰ روز را بازیابی نمی‌کند. خروج جزئی، یک دیل خروج مستقل است. زمان تاریخی با اختلاف فعلی ساعت بروکر و GMT تبدیل می‌شود؛ تغییر DST بروکر می‌تواند زمان‌بندی گزارش تاریخی را جابه‌جا کند.

## مدیریت سرور و نگهداری

```bash
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 caddy
bash deploy/backup.sh
```

اسکریپت بکاپ از SQLite با API بکاپ نسخه سازگار می‌گیرد و `.env` متناظر را همراه آن ذخیره می‌کند. بکاپ شامل اطلاعات خصوصی و کلید رمزگذاری است؛ هر دو را با هم و خارج از سرور نگه دارید. بازیابی باید با توقف برنامه و جایگزینی فایل دیتابیس و `.env` متناظر انجام شود؛ بازگردانی کور دیتابیس هنگام وجود سفارش در حال اجرا، ممکن است وضعیت سفارش را عقب ببرد و پیش از شروع دوباره به تطبیق History بروکر نیاز دارد.

`REGISTRATION_ENABLED=false` ثبت‌نام عمومی جدید را می‌بندد. ورود کاربران موجود ادامه دارد. نسخه فعلی پنل مدیر سراسری، بازیابی ایمیلی رمز، MFA، پرداخت اشتراک و نظارت تجاری بر کاربران ندارد. مالک سرور تنظیمات عمومی را از `.env` کنترل می‌کند.

معماری این نسخه **یک سرور، SQLite/WAL و یک worker** است. چند worker، کپی موازی برنامه یا مقیاس چندسروره در این بسته پشتیبانی نشده است. پیش از سرویس عمومی با تعداد بالای حساب، به آزمون بار، انتقال ذخیره‌سازی به PostgreSQL، مدیریت ترمینال‌های مجزا، مانیتورینگ و سیاست نگهداری داده نیاز دارد. داده تاریخی فعلاً خودکار پاک نمی‌شود. استفاده عمومی/تجاری هنوز نیازمند تعیین الزامات عملیاتی و مقررات محل فعالیت است.

## آزمون‌ها

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check app/static/app.js
```

برای آزمون DOM رابط، Node.js و jsdom لازم است:

```bash
npm install --no-save --package-lock=false jsdom
node tests/frontend.cjs
```

این آزمون‌ها اتصال بروکر، کامپایل MQL5، صدور گواهی روی دامنه واقعی یا ارسال واقعی تلگرام را تأیید نمی‌کنند. WebRequest اکسپرت داخل Strategy Tester اجرا نمی‌شود؛ برای آزمون رابط از حساب دمو استفاده کنید و بک‌تست منطق استراتژی را جداگانه انجام دهید.
